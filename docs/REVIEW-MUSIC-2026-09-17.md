# 音乐与 AI 电台修复验收

源码版本：`326acdb7f174fb085527a0bd57b7d2572cc8f579`。
范围：音乐生成、作品持久化、频道播放及作品库入口。由同一实现者完成验证，
不是独立安全审计；没有修改 Mac 网络设置，也没有公开用户作品或真机原始日志。

## 根因与修复

- 旧音乐实际仍在服务端，但设备没有恢复作品状态，页面看起来像从未生成。
- 原电台选频道只修改提示词；现在可以直接生成频道音乐，也可先语音描述。
- 同步请求容易随网络超时失去结果。改成幂等、持久后台任务；设备只查询结果，
  不因超时自动再次调用付费模型。服务重启时根据已入库成果恢复，否则明确标记中断。
- 原响应上限没有算入双声道 PCM 与 hex 的四倍开销；用三分钟音频夹具重现了失败，
  并验证修复后的完整入库及单声道数据。最终 PCM 仍有独立的 12 MiB 上限。
- 音乐入口直接打开“我的音乐”；桌面作品相册仍显示全部类型，两者离线列表缓存分开。
- 播放按钮再次点击停止；播放和生成期间可以切出应用。

## 验证结果

- 服务端 97 项测试通过，包含鉴权、幂等、断线、重启、旧作品保留和音乐筛选。
- 恢复原 20 MiB 限制的受控变异，被三分钟双声道回归测试拒绝。
- 真机通用 UI 回归 81 项全部通过，包含滑动、中文、设置、音量、Wi-Fi 页面、
  频道状态以及过短录音退出；Wi-Fi 测试仅扫描、打开并取消输入，没有改网络。
- 真机找回旧音乐，向扬声器输出；切回时钟仍继续，停止按钮有效。
- 通过正常电台按钮真实生成一次星空音乐，后台完成并入库。
- 新曲约 197.973 秒，完整向音频驱动写入 6,335,148 字节，无提前结束。
- 服务器重启后任务仍为完成，两首音乐仍可查询；设备重启后恢复并再次播放。
- 旧作品内容哈希前后相同。照片、壁纸、NVS 和内容分区未重写。
- 实际 mTLS 连接缺少 Bearer Token 时读取音乐状态为 401。
- Bandit 无中高危发现；依赖审计无已知漏洞；公开树隐私检查通过。

本次没有再生成额外的语音定制歌曲，也没有真实切断服务器电源；对应故障分支
使用隔离测试验证。以上播放证据是硬件音频驱动成功写入完整数据，不是声学音质评测。

python tools/test_music_device.py
python tools/test_music_device.py --generate --full-playback
